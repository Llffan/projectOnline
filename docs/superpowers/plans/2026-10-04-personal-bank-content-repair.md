# 个人银行开户内容修复计划

日期：2026-10-04

## 目标与边界

个人开户入口、国家切换、银行详情必须始终对应个人账户内容。同步中文与英文，保留现有样式、图片、动画、公司开户路由。此次不执行此前的渐进式前端重构计划。

## 阶段一：收齐并核验银行资料

用户新增要求：先找齐各个个人开户银行的信息，再进入下一步新增页面。参考 https://www.changjiajie.com/hong-kong-construction-bank/，第三方信息作为检索线索；开户资格、文件、费用等以银行官方页面、官方 PDF 和条款交叉核验，不直接复制营销描述。

范围：现有个人导航和银行卡片中的香港17家、新加坡9家、澳门7家、美国7家，合计40个入口。所有银行都需要调查，但不是所有入口都应被认定为支持目标客户个人开户。

逐家记录：准确银行主体、个人账户产品、适用年龄/居留身份/税务身份、是否接受内地或非居民申请、办理地点/在线/面签/见证渠道、身份证件、住址与资金来源证明、个人税务声明、办理步骤、账户功能、最低入金与结余、开户与维护费用、账户维护、来源链接、核验日期、争议及缺项。

资料状态区分：来源候选、已读核验、尚缺材料、不适用于普通个人、主体待核对。搜索摘要、通用介绍、公司开户资料及旧营销文章不能作为资料已齐的证据。

- [x] 盘点40个现有入口和公司组件误复用问题。
- [x] 对每个银行发起首轮资料检索，建立来源候选台账。
- [ ] 逐页核对所有候选资料；补齐个人产品、申请资格、文件、流程、费用和维护。
- [ ] 核对特殊银行主体及个人业务适用性；形成保留/暂缓/不适用结论和证据，不擅自假设均能开户。
- [ ] 收齐后整理中文内容草稿及对应英文草稿，明确无法公开确认的信息，不编造门槛或承诺。

**进入下一阶段的门槛：**40个入口逐一有可追溯的调查结论；拟新增详情的银行拥有明确的个人业务依据和足够内容；未确认、不适用或主体有争议的入口已有明确处理方案。仅找到链接不算通过。实施时按资料覆盖分别处理：依据明确者提供个人资料；依据不足者仅保留待确认说明，不作为已核验申请方案。完整缺项见资料台账。

## 阶段二：修复个人导航

保留个人路由 /bank/{region}/personal/{bank} 与英文 /en/bank/{region}/personal/{bank}。根据选中的国家生成个人银行列表，避免只有原国家保留 personal 而切换国家变成公司路由。导航、银行卡片、当前银行高亮和语言前缀采用相同银行标识。公司导航保持原路径。

## 阶段三：新增个人银行详情

停止个人 BankDetail 加载 bank_company 页面。沿用现有视觉结构，按核验后的银行内容数据呈现个人账户介绍、适用人群、资料、申请流程、费用/维护、常见问题和咨询入口。先香港，再新加坡、澳门、美国；同步英文。通用内容可共享，具体银行条件不能用同一份通用文案替代。

## 阶段四：验收

逐一检查所有获准发布银行的中英文路由，覆盖顶部入口→总览→银行、跨国家切换、跨银行切换、刷新、返回和语言版本。个人详情不得加载公司材料或公司组件；公司流程不受影响；样式、背景与动画保持现状。运行 npm run build，记录结果和资料覆盖情况。

## 当前发现

个人 BankDetail（中英文）加载公司银行组件；共享银行导航在跨国家时返回公司路径。资料首轮发现私人银行定位、企业业务定位及澳门银行主体命名问题，需先核验，不能以现有名单直接生成40份个人开户页。
